## 少数推論から区間化までの試行

11月2日に検討した区間化の試行を、本人の「それがいいね」により採用した。[D013](../../../方針変更履歴.md)
本注釈前に確認修正まで一周する工程として、P05の成果物と完了条件に含める。具体的な設定値は試行で確認する。
割当済み開発患者の短い連続範囲から時刻付き画像を抽出し、予測を時刻順に並べ、区間候補へ変換して元動画と照合する。
確認するものは、完全見逃し、候補の細切れ、開始終了のずれ、過剰な除外、人が直す箇所である。
抽出で手が画像に現れない失敗、入力画像の誤判定、区間化による失敗を区別する。
フレーム予測をどの時間範囲へ適用するか、隙間の結合、前後の余裕は未確定とし、正解の区間境界を予測へ流用しない。
動画やROIの適用範囲をまたいで候補をつながず、未推論、判定不能、推論失敗を陰性へ変換しない。
元の回答と時刻付き予測を保持し、区間化は別の処理と実行IDで入力予測と設定を参照する。
後処理の変更で再推論をせず検討できる形にし、本評価用の条件固定と性能測定は後の工程で行う。
採用は計画上の決定であり、区間化の実装や推論の実施を意味しない。

## 作業と記録の置き方

- `scripts/`：保存して実行する処理コード。
- `configs/`：実行条件。実行時の確定設定は各runにも保持する。
- `runs/<実行ID>/`：manifest、実行時コード、入力の識別、環境、結果、失敗、確認記録。

共通コードを再利用した場合も実行時コードを保存し、再実行は別IDにする。
出典調査や判断の記録もこの工程のREADMEと成果物からたどれるようにする。
動画、画像、ラベル、患者対応、重み、機微なログは共有記録へコピーしない。
発表に採用する結果は[発表根拠の対応表](../../../スライド/発表根拠の対応表.md)へ実行IDと成果物を登録する。
[共通の作業運用](../../../共通/作業フォルダと発表根拠の運用.md)に従う。
