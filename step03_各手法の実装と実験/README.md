# step03 手法別の実装と実験

## 目的と現在地

M1、M3、M2を別の工程で実装し、共通の比較へ予測と設定を渡す。
モデル用コード、実データの推論、学習、性能測定は未実施。
環境確認手順と質問ドラフト、今回の手法別計画が準備済み。

## 入力と出力

動作確認の入力は、用途を割り当てた試行患者の少数データと候補モデル。
比較用実験の入力は、共通データの学習患者と調整患者、原典に基づくモデル条件。
出力は重み、生成原文と解析結果、全対象の予測と失敗、採用設定、時間とメモリ、実行記録。

## 手法別の工程

| 入口 | 動作確認 | 共通データでの実験 |
|---|---|---|
| [M1 学習なしQwen](M1_学習なしQwen/README.md) | P05：読込と少数推論、回答保存 | P08：質問と推論条件を調整患者で決める |
| [M3 論文手法](M3_論文手法/README.md) | P06：原典対応、IR実装、少数更新と保存再読込 | P09：共通データで学習して重みを選ぶ |
| [M2 追加学習Qwen](M2_追加学習Qwen/README.md) | P07：M1と同じ基盤で更新と再読込 | P10：共通データで追加学習して重みを選ぶ |

M1の推論とM2の追加学習が成立してから主比較の基盤モデルを決める。
M3の実装はQwenの完了を待たずに進められる。
M1とM2は基盤版、入力、質問、推論条件をそろえる。
M2とM3は学習患者、動画、正解、抽出対象を共有する。

## 保存場所

手法専用の新しい実装と設定は各手法のフォルダで管理する。
既存の`scripts/`と`configs/`は共通処理と既存ドラフトの場所として保持する。
新規実行は各P工程内の`runs/<実行ID>/`へ保存し、`method_id`と`operation`で方式と処理を識別する。
親の既存runsは元の場所に保持する。
学習、推論、採点は別の実行IDにし、完了済みの実行は移動や上書きをしない。
元動画、ラベル、重みはGit対象外の登録先を参照する。

## 完了条件

各方式について動作確認と比較用実験を別に判定する。
P08からP10の採用設定、重み、調整予測、測定記録をP11へ渡せたら、比較準備を完了とする。
P11で全条件を固定した後、P12の最終評価用推論を新しい実行として行う。
少数動作確認だけで最終比較を完了としない。

[全工程の依存関係](../研究計画_詳細.md)、[環境確認と少数実験](環境確認と少数実験.md)、[質問のドラフト](configs/prompt_draft.txt)を参照する。
