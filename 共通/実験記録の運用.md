# 実験記録の運用

## 日報と実行結果

日報には作業の経緯、判断、失敗、次の作業を記録する。
実行ごとの入力、コード、設定、環境、出力は`runs/<実行ID>/`へ保存し、日報からリンクする。
同じ条件での再実行や途中再開も新しいIDで記録し、親の実行IDを残す。

## モデル実験の記録

| ファイルまたは項目 | 内容 |
|---|---|
| manifest.json | 目的、状態、開始終了、実行コマンド、コードと入出力の対応 |
| config.json | 引数と既定値を反映した設定、質問、前処理、乱数シード |
| inputs.csv / outputs.csv | 入出力の役割、識別子、保存先、必要な内容識別値 |
| environment.json | Python、ライブラリ、CUDA、GPU、OS |
| requirements-lock.txtなど | 実際に使った環境の固定情報 |
| code_snapshot/ | 実行時の自作コードと利用実装の版 |
| logs/ | 実際の標準出力とエラー |
| artifacts/ | 予測、重み、集計、図など |
| 実行結果.md | 目的、結果、制約、検証、再実行方法 |

既存の記録方針は[保存コピー](../スライド/references/研究全体方針.md)にある。
そこに書かれた`research_tools/run_record.py`などの実在と、この研究での再利用方法は未確認である。
記録用コードを確認または整備し、少数のモデル実験から組み込む。
文書だけ整備した状態を、記録機構の実装完了とは扱わない。

## 軽量な出典確認

文献やOSSの出典確認は、保存した確認コード、取得日時、公式URL、得たメタデータ、失敗、出力のSHA-256を残す。
モデル実験用の重みや予測が存在しない場合、空の成果物を作って実施済みに見せない。
今回の公式メタデータ確認は、この軽量な記録に該当する。

## 既存結果

過去の実行を後から整理するときは「後から整理」と明記する。
現在のコードを保存しても、過去の実行時コードと同一だった証明とは扱わない。
保存されていない条件は未記録として残す。
