# P01 検出対象と比較の問いを具体化

## 目的

この工程では「検出対象と比較の問いを具体化」を行う。
全体の順番と条件は[研究計画](../../研究計画_詳細.md)、現在地は[状態JSON](../../research_state.json)を参照する。

## 入力

既存の研究方針、本人確認済みの事項、利用可能な資料。
患者の用途と分割を確認し、研究データの本体はGit対象外の登録先を参照する。

## 出力と完了条件

成果物は「対象の定義案、比較表、原論文の条件対応表」。
成果物と対応する実行ID、検証状況、未解決点を示せたら、この工程の完了を判定する。
動作確認、実行終了、記録検査、性能評価、再現確認を区別する。

## 現在地

定義と比較設計を検討中。モデル実験は未実施。
固定ROIと区間化の議論を踏まえ、[研究全体の構成](研究全体の推奨構成_20261102.md)を本人が採用した。目的を具体化し、少数推論から区間化と確認修正までを本注釈前に一周する。詳細な判定規則と設定値は未確定。
先に作成した[研究計画の批評](研究計画の批評_20261102.md)は提案時点の記録として保持し、採用内容はD013と現行計画を参照する。工程全体は検討中である。
計画上の状態は状態JSONの`P01`で管理し、確認済みの実行IDを以下へ追加する。
管理構成の確認として、[20261102_workflow_layout_check_01](runs/20261102_workflow_layout_check_01/実行結果.md)を実行した。
これは工程フォルダと文書参照の確認であり、検出対象の確定やモデル実験の完了ではない。

## 作業と記録の置き方

- `scripts/`：保存して実行する処理コード。
- `configs/`：実行条件。実行時の確定設定は各runにも保持する。
- `runs/<実行ID>/`：manifest、実行時コード、入力の識別、環境、結果、失敗、確認記録。

共通コードを再利用した場合も実行時コードを保存し、再実行は別IDにする。
出典調査や判断の記録もこの工程のREADMEと成果物からたどれるようにする。
動画、画像、ラベル、患者対応、重み、機微なログは共有記録へコピーしない。
発表に採用する結果は[発表根拠の対応表](../../スライド/発表根拠の対応表.md)へ実行IDと成果物を登録する。
[共通の作業運用](../../共通/作業フォルダと発表根拠の運用.md)に従う。
