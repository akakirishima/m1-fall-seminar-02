# 今後の資料作成で参照する資料とルール

整理日：2026-10-20

今回のゼミ資料の制作で使った指示書、変更記録、確認できた会話上の指示を、次回参照できる形に整理した。
元のMarkdownを現在読み直し、配色と用語については該当する過去の会話記録も確認した。
ここにあるのは制作上の指定と運用方針であり、完成した全スライドがすべて適合していたことの保証ではない。
スライドの再描画や研究コードの実行は、この整理では行っていない。

## 2. 指示が食い違ったときの扱い

1. 今回のユーザーの明示指示を優先する
2. 今回指定された基準資料と、指定された対象範囲を守る
3. 同じ項目について後から更新された指示を適用する
4. 古い指定は履歴として扱い、今回のルールへ混ぜない

数値の正誤は、対応する保存結果と実行条件で確認する。
デザイン見本や文章の指定を根拠に研究結果を書き換えない。

| 項目 | 確認できた変更 | 次回の使い方 |
|---|---|---|
| 強調文字 | 10月17日版は赤 #FF0000。10月19日添付版は青 #0070C0で、旧赤太字指定より優先すると明記 | 10月19日添付版を使う場合は青。既存Web版には赤を指定した履歴もあるため、全ページへの反映済みとは扱わない |
| 句点 | 10月19日添付版とDice、IoUの制作依頼で禁止 | その書式を適用するスライドの編集可能な文章から「。」を除く。読点「、」は可。元画像の文字は改変しない |
| 参考画像の配色 | Dice、IoUの3枚で青系の参考画像が提示された後、他のスライドと同じオレンジ基調にする指示があった | 参考画像の配置を使い、デッキの装飾をオレンジに合わせる。青い強調文字とオレンジの装飾は両立する |
| 文字サイズ | 本文最小18pt、下部のまとめ24ptへ更新された | 古いWeb画像の小さいラベルを、そのままPowerPointの基準にしない |
| 作成枚数と発表時間 | 制作中に何度も変更され、時間配分の調整が保留された時期もある | 次回の時間、質疑の扱い、掲載範囲から決め直す |

## 3. 資料の構成と説明のルール

### ゼミで継続する構成

中心の指示書では、石川さんの目次を参考に次の6項目を指定していた。

1. 研究背景、目的
2. 前回の課題、展望
3. 今回の概要
4. 今回の取り組み
5. 課題、今後の展望
6. 付録

元の見出し表記は「研究背景・目的」「前回の課題・展望」「課題・今後の展望」である。
6項目は6枚という意味ではない。
表紙と目次はこの前に置く。
今回の実際の制作では「まとめ・今後の展望」への変更も記録されているため、次回は指定する基準資料の見出しを確認する。

- 研究背景と目的は既存スライドを再利用し、明示された変更依頼がなければ文章、図、順序、基本配置を変えない
- 前回発表時点の課題と、今回分かった課題を分ける
- 「前回の問題 → 今回確かめる問い → 手法と条件 → 結果 → 残った課題と次の確認」を対応させる
- まとめでは、実施した作業の列挙に加えて、結果から何を確認できたかを書く
- 各結論から根拠となる結果ページへたどれるようにする
- 付録には詳細条件、全結果、用語、追加例、出典を置く。主張の解釈に必要な条件と重大な制約は本編に残す

### 手法説明

- 「なぜ使うか → 全体像 → 各工程」の順に進む
- 各工程は、入力、行う操作、出力を示す
- 同じ全体図を再掲し、工程の順序と位置を保つ。説明中の工程を赤枠で示す
- 名称だけの箱を並べず、同じ画像の処理前後や途中結果を対応させる
- 説明用に省略した構造と、実際に使った構成を区別する
- 既存手法の導入、公開実装の利用、本研究で加えた変更を区別する

### 結果説明

- 数値ページは「上に比較条件 → 中央に表やグラフ → 下に読み取り」を基本にする
- 画像ページは「上に条件と凡例 → 中央に大きい実画像 → 下にその例から分かること」を基本にする
- 数値と短い考察を近くに置く。実画像が小さくなる場合は別ページへ分ける
- 比較では同じフレーム、同じ切り出し範囲、同じ倍率、同じクラス色を使う
- 局所拡大には、元画像のどこを拡大したかも示す
- 良い例と残る誤りを示し、例の選び方をノートへ残す
- 1枚の画像からの観察は「この例では」とし、平均的な性能の根拠は全評価データの集計に求める
- 「1実験2枚」は配置の出発点であり、全結果を2枚へ削る固定規則ではない

参考にしたのは、中嶋さんの課題から手法への接続と比較表、石川さんの全体図と途中結果、内倉さんの大きな実画像と下段の観察である。
先輩資料の研究成果、数値、写真、配色のすべてをそのまま転用する方針ではない。

## 4. 書式の共通ルール

以下は10月19日添付版を使う場合の要約である。
細かな座標、グラフ、数式の指定は保存コピーを参照する。

| 要素 | 指定 |
|---|---|
| 画面 | 4:3、25.4×19.05cm、白背景。Web版の制作座標は1200×900px |
| 書体 | 日本語も英数字もメイリオ。数式の記号はCambria Math |
| タイトル | 28pt、太字、黒 |
| 小見出し | 20pt、太字 |
| 本文、表、図中ラベル、注記 | 18pt。出典とページ番号を除いて18pt未満へ縮めない |
| 下部のまとめ | 24pt、青、太字、中央寄せ。長くて収まらない場合だけ18ptまで可 |
| 出典 | 9pt、灰色 #656565 |
| ページ番号 | 12pt |
| 通常文字 | 黒 #151515 |
| 強調文字 | 青 #0070C0の太字 |
| 注目枠 | 赤 #FF0000、2ptの四角、塗りなし、角丸なし |
| 装飾 | 既存のオレンジの見出し線を引き継ぐ |
| 表 | 見出しは #F79646と白太字。データ行は #FCDDCFと #FDEFE9を交互。罫線は白 |
| 数式 | PowerPointの数式機能で編集可能に作る。独立した式は20pt、薄橙 #FFF4EAの背景 |

- 本文左の装飾用縦棒は、色を問わず禁止。引用風の左罫線や帯の左端の色線も使わない
- 文字を自動縮小して詰め込まない。まず画像や余白を調整する
- 書式変更だけを頼まれた場合は、文言の削除や言い換えをせず、収まらない箇所を報告する。句点の削除は10月19日版で認められた例外
- 内容の再構成も依頼された場合は、ページ分割やノートへの移動を検討する
- 画像の縦横比を保ち、結果やマスクを描き直さない
- 新規の文字、表、工程図、数式は編集可能にする。スライド全面を画像として貼って完了にしない
- 背景や過去の固定ページを画像で再利用する場合は、そのページの編集上の制約を示す
- 全ページを同じ箱の並びにせず、比較表、実画像、工程図など内容に合う型を使う
- 研究画像のクラス色と、文字の強調色を分ける。クラス名と凡例も添える

小見出し20pt、ページ番号12pt、複数系列グラフの2色目以降などは、当時アシスタントが補った値と書式指定書に明記されている。
すべてをユーザー本人が直接決めた値として説明しない。
また、旧Web版の画像ラベルなどは13〜15pt相当のページがあり、PowerPoint向け18pt指定を満たすとは限らない。

## 5. 用語と文章のルール

- 英語の略語は、表紙からの読み順で初出を「正式名称（略語）」とし、以後は略語を使う
- 図、表、見出し、画像内の文字が本文より先に出る場合も初出として確認する
- Diceなど人名由来の名称に架空の正式名称を作らない
- 専門外の聞き手にも分かる短い日本語の機能説明を添える。詳細な用語説明は付録へ置く
- 図を文章で丸ごと繰り返さず、図の見方と注目する差を書く
- 「有効」「精度向上」「課題が残る」だけで終えず、条件、指標、変化量、失敗場面を具体化する
- スライド内の編集可能な文章では句点「。」を使わない。説明用Markdownや発表ノートまで句点禁止にする指定とは区別する

研究用語は、10月19日の用語整理で次のように区別した。

| 対象 | 表記と意味 |
|---|---|
| 研究目的、研究室映像、最終適用先 | 新生児 |
| 公開データ、データセット名、先行研究の対象 | 内容に応じて乳児を残す。一括して新生児へ置換しない |
| 技術の名称 | 身体部位セグメンテーション |
| 部位を推定する処理 | 部位推定 |
| 得られる領域の表現 | 部位マスク |
| 人が正解を付ける作業 | アノテーション |
| 画素ごとのクラス | 部位ラベル |
| 評価に使う正解 | 正解部位マスク。Ground Truth（GT）を定義後はGT |
| 動画中の画像と件数 | フレーム、代表フレーム。評価対象は1,256フレーム |
| 研究室の対象映像 | 研究室の新生児映像 |

「分割分岐」「分割単独」などのモデル内の名称、キーポイントや枠の「正解」は別の意味を持つため、機械的に置換しない。
この用語整理は会話に分散しており、今回この一覧へまとめた。

## 6. 研究結果と画像の扱い

- 論文の仕様、公開実装、本研究の追加、保存済み結果、未実施事項を分ける
- 部分的な一致だけで「論文再現が完了」と書かない
- 公開乳児データでの定量評価と、正解のない研究室の新生児映像への試験適用、目視確認を区別する
- 研究室映像の出現フレーム数を精度に読み替えず、正解なしにDiceやモデルの性能順位を主張しない
- 比較表では、Test、評価座標、入力解像度、学習情報、モデル選択、位置指定、指標の集計法を確認する
- 論文のRGB参考値と今回の白黒実測値を分ける。条件が異なる値から一般的なモデルの優劣や原因を断定しない
- ポイント差と相対増減率を区別する。全体Diceを部位別Diceの単純平均として説明しない
- 説明用の計算例や出力構想は、その旨を明記して実測値と区別する
- セグメンテーションの精度から、運動特徴量、キーポイント改善、医学的有効性まで達成したと書かない
- 左右を同じクラスとして扱ったマスクから、左右別の運動を測定できたとは言わない

### 説明画像と結果画像

- 目的、手法、展望の説明には、形の分かる保存済み正解マスクを使ってよい。「説明用」「正解」と明記する
- 正解を使った図を、実際の推論入力やモデルの予測出力として扱わない
- 結果、比較、失敗分析には保存済みの実予測を使う。見栄えのために正解へ置換しない
- 穴埋め、輪郭修正、平滑化などで予測精度を装わない
- 各画像のデータ名、分割、元フレームID、条件、出典番号を追跡できるようにする
- 実行ID、元ファイルのパス、親実行、切り出し範囲、ハッシュはノートや台帳へ残す。長いパスをスライド本文へ詰め込まない
- 元映像、正解ラベル、本研究の予測の出典を区別する
- 動画が抜粋なら長さとループ再生を明記する。今回の「6秒、2秒」は該当素材だけの条件

資料作成に伴って研究結果を新しく計算する必要が生じても、明示された実行依頼がなければ学習、推論、評価、研究用集計などを実行しない。
保存コード、条件、入力、出力先と記録方法を準備し、静的レビューと手順整備まで進める。

## 7. 作業と確認のルール

- 編集前の版を残し、元の結果を上書きしない
- ユーザーが複数案を求めた場合は、同じ内容で比較できる実際の見本を作る。文章の提案だけで代えない
- 仮案の比較を頼まれたときは、本番への採用と区別する。通常の編集依頼すべてに追加承認を求めるという意味ではない
- 指定スライドの書式修正では、他ページ、マスター、スライドサイズを勝手に変えない
- 全体の一覧と各ページの拡大表示を確認する
- 重なり、欠け、はみ出し、文字サイズ、余白、画像倍率、凡例、条件名を確認する
- 用語変更やスライド移動後は、略語の初出、ページ参照、目次リンクを確認する
- 用語検索やビルド成功だけで、見た目の確認を完了扱いにしない
- Web版で確認した内容と、PowerPoint版の確認を分ける。PDFだけで動画、アニメーション、編集可能性を確認済みにしない
- チェックは実際に確認した項目だけに付け、証拠と残った問題を記録する
- 最後に変更点、確認した範囲、未確認事項を短く報告する

今回の過去記録には、用語変更時に16ptへ縮小したという別AIの報告があり、18pt指定と衝突している。
それを新しい許容値にしない。
また、用語変更後の最終可読性が未確認の記録もあるため、「修正したという報告」と「表示を確認したこと」を分ける。
