## 1. 最優先で守ること

### 英語の略語は、初出で正式名称を示す

- 表紙から読む順で、初出は「正式名称（略語）」、2回目以降は略語とする。「略語（正式名称）」の順にしない。
- 例：SiamParseNet（SPN）、You Only Look Once（YOLO）、Segment Anything Model 2（SAM2）、Multi-source Inference（MSI）。
- タイトル・本文・表・図中・画像内を確認する。本文より先に図や出典で未説明の略語を出さない。
- 正式名称が長い場合は図表の直前へ記載し、図中や見出しを無理に長文化しない。
- 元PDFの画像を保持し、必要な表記だけ編集可能な文字を重ねる。略語の表記変更はこのルールを優先する。
- 本編で説明済みの語は付録でも略語を使用する。付録で初登場する語も正式名称を先に示す。
- Diceは人名由来の名称で、頭文字の略語として展開しない。製品・ファイル名、変数記号、単位にも架空の正式名称を作らない。
- 初出ページと正式名称は `web_slides/revision-manifest.json` の `abbreviationFirstUses` に記録し、ページ順を変更したら見直す。

### 全体構成は、次の6項目と順番を固定する

1. **研究背景・目的**
2. **前回の課題・展望**
3. **今回の概要**
4. **今回の取り組み**
5. **課題・今後の展望**
6. **付録**

- この構成は、ユーザーが提示した石川さんの発表目次の画像に合わせた指定である。
- 研究背景・目的は毎回同じ既存スライドを使う。文章、図、目的の表現、掲載順、基本レイアウトを勝手に変更しない。
- 研究背景・目的を短縮・再解釈・再生成しない。新しい成果との接続は第2項・第3項で行う。
- 研究背景・目的を修正してよいのは、ユーザーがその変更を明示的に依頼した場合だけ。
- 第2項は前回発表時点の課題と展望、第5項は今回の結果を受けて残った課題と次の計画を扱う。両者の時点を明確にする。
- 撮影環境・データ、方法、実験結果、今回のまとめは、第4項「今回の取り組み」の小見出しとして置く。必要な項目をその回の内容に応じて選ぶ。
- 表紙と発表目次は上記6項目の前に置く。付録は目次に記載し、本編の後に置く。
- 6項目は6枚という意味ではない。1項目に複数ページを使い、枚数と説明時間は今回の発表条件に合わせる。
- 新しいユーザーの指示がこのファイルと異なる場合は、新しい指示を優先する。

### 作る資料の性格

研究室の聞き手が「なぜこの取り組みが必要か」「どう処理したか」「何が分かったか」を追える研究報告にする。
実データ、処理前後の画像、条件、比較結果を中心に構成する。
参考にするのは、中嶋さんの課題から手法への接続、石川さんの全体図と処理途中の説明、内倉さんの実画像を使った結果説明である。
研究内容・実績・数値・写真を他の人の資料から自分の成果として流用しない。

## 2. 最初に読む資料と決める事項

### 資料の優先順位

1. 今回のユーザー指示。
2. ユーザーが基準として指定した自分の既存PPTXまたはPDF。

基準資料にある余白、見出し、色、ページ番号、大学・研究室の表記を引き継ぐ。
参照した先輩ごとの色やフッターを1つの資料内で混在させない。

PDFしかない場合は背景・目的のページを見た目ごと保持できるが、その部分が編集可能な文字や図になるとは限らない。その違いを納品時に伝える。

### 発表ごとの情報

作業開始時に次を記録する。資料から分かる項目は先に埋める。

| 項目 | 記録すること |
|---|---|
| 発表 | 日付、発表名、発表時間。質疑込みかも分かれば記録 |

## 3. 各項目の作り方

### 1. 研究背景・目的

**役割：毎回共通の研究全体の必要性と目的を共有する。**

既存スライドをそのまま使う。
その回の実験に合わせて研究全体の目的を狭めたり、目的文へモデル名や今回の結果を足したりしない。
固定ページに疑問点や古い表記を見つけた場合は作業メモへ記録し、本文へ無断で反映しない。
第2項の冒頭で「この目的に対して、前回どこまで進み、何を次の課題としたか」へつなぐ。

### 2. 前回の課題・展望

**役割：前回発表の終わりに残した課題と、予定していた次の作業を共有する。**

前回の資料や記録を読み、前回までの到達点、課題、今後の展望を簡潔に再掲する。
必要なら前回の実画像や結果を1つ添え、どの場面・部位・処理で困っていたかを示す。
「精度が低い」「課題がある」で終えず、何ができなかったかを書く。
原因が確定していない場合は「原因の仮説」とする。
今回発見した問題を、前回から分かっていた課題として書き換えない。
前回の記録が見つからない場合は、その情報が未確認であると設計書へ記録する。

### 3. 今回の概要

**役割：前回の課題のどれに対し、今回は何を行ったかを先に見渡せるようにする。**

前回の課題と今回の対応を、短い対応表または全体図で示す。
今回扱う範囲、今回確かめる問い、取り組みの順番を簡潔に示す。
例：「RGBで学習したモデルを白黒入力へ適用したとき、分割性能はどう変わるか」。
まだ扱っていない課題は「今回の対象外」「次回以降」など、状態が分かる表記を付ける。
詳細な手順、全条件表、全結果をここへ集約せず、第4項への地図にする。
研究全体図がある場合は、今回の対象範囲へ枠を付けて示す。

### 4. 今回の取り組み

**役割：今回実施した内容を、必要性・方法・結果・考察まで具体的に報告する。**

この項目を本編の中心にする。
3つのまとまりの境界に章扉を置く。本編の手法詳説はSPNとYOLOとし、MSIはSPNの伝播処理として扱う。
今回の取り組みは「使用する手法 → 共通の実験条件 → 実験ごとの条件・結果・考察」と進める。手法の詳説は前半へまとめる。
データ・分割・指標・基本学習条件は先に説明する。各実験では変更点を短く示し、数値と考察を同じページで対応させ、次に大きな実画像を見せる。
取り組みを細分化しすぎず、第3項で示した問いと説明順を揃える。

#### 4.1 使用する手法・処理構成

前回の課題に対し、どこをどう変えたかを説明する。
中嶋さんN06 p.8–12の「弱い結果 → 実例 → 仮説 → 手法」を参考にする。

最初に「入力 → 処理 → 出力」の全体図を置く。
各工程に、可能ならその工程の実際の入力・中間出力・最終出力を小さく添える。
今回扱った範囲を枠と文字で示し、既存処理と今後の処理も分かるようにする。

続く詳細ページでは、全体図の工程順と位置を保つ。
今説明している工程へ枠を移すか、対象外を薄くする。どちらかの方式に統一する。
説明順は「必要な理由 → 入力 → 行う操作 → 得られる出力」とする。
抽象語だけで終えず、同じ画像の処理前後、一つの画素、短い時間列などの具体例を置く。

石川さんI02 p.9–10・12・20・26・32・34の全体図、中嶋さんN06 p.13–24の段階説明を参考にする。
同じ全体図や入力画像を再掲することには意味がある。再利用時は位置・ラベル・色を揃える。
全体図に全層名や全パラメータを詰めず、今回の説明に必要な工程を読める大きさで残す。

SPNとYOLOの仕組み・今回使った範囲は本編で説明する。SAM2の処理フロー・更新部分・細かな学習パラメータは付録A52〜A54へ移す。YOLO＋SAM2の比較条件と結果は本編に残す。今回のSPNでは「全体構造」「特徴抽出」「分割分岐」「伝播分岐」「今回の学習・推論範囲」の5枚を置く。各ページで同じ工程図を再掲し、説明中の工程を赤枠、その他を薄くする。主比較の分割分岐単独とMSIの伝播利用を同じ図で示し、細かい損失や学習設定は付録へ置く。過去の英論発表から再利用する場合も、先行研究の説明と今回実施した範囲を明記する。

比較実験の条件と評価指標は、結果を読む前に説明する。
モデルごとの入力、学習条件、出力、共通条件、相違条件を対応づける。
一般的な既存手法の導入・適用では「既存手法」「今回の構成」「今回変更した点」を正確に書き、独自モデルを発明したように表現しない。

#### 4.2 共通の実験条件・データ・評価方法

どんな映像・画像を使い、何を評価したのかを説明する。
撮影場所やカメラ配置は実写真・配置図で示し、解釈に必要な条件を表へまとめる。
候補項目は撮影機材、解像度、fps、対象数、撮影期間、遮蔽など。今回の取り組みに必要な項目を選ぶ。

複数のデータを使う回では、次の対応を示す。

| データ | 入手・撮影元 | 何のために使ったか | 今回の使用範囲 |
|---|---|---|---|
| 研究室・病院の撮影データ | 確認した場所と期間 | 研究全体の対象、適用確認など | 今回評価した／今回の数値評価には未使用 |
| 公開データ | 正式なデータセット名 | 学習、比較、予備検討など | 使用した分割と件数 |

入力画像と正解ラベルを並べ、対象クラスとラベルの意味を示す。
学習・検証・Testの分割を説明し、件数が画像数か動画数か対象人数かを明記する。
研究室の撮影条件を、公開データ実験の条件であるかのように並べない。

#### 4.3 実験ごとの条件・結果・考察

第3項で示した今回の問いに、数値と実例で答える。

主な結果ごとに、次のまとまりを作る。

1. 比較する条件と評価対象を短く示す。
2. 問いに直接答える表・グラフを示す。
3. 同じ入力の予測画像や失敗例を示し、数値の意味を説明する。
4. 分かったことと、その結果だけでは判断できないことを書く。

一つの実験は複数ページでよい。数値と短い考察は同じページへまとめ、画像の比較は別ページへ大きく置く。条件・数値・画像を無理に1枚へ詰め込まない。
最初の表に全指標・全条件を載せず、主な問いに必要な列を残す。詳細表は付録に置ける。
モデル名の順で結果を並べるだけでなく、第3項の問いと同じ順で説明する。

中嶋さんN06 p.32の「変更条件が分かる表＋読み取り」と、内倉さんU05 p.21–26の「条件＋大きい実画像＋下段の観察」を参考にする。
画像の比較は同じフレーム、同じ切り出し範囲、同じクラス色、同じ画像サイズに揃える。
小さな誤りは局所拡大し、元画像の拡大位置も枠で示す。
良い例、悪い例、代表例の選定理由をノートに残す。

画像1枚からの観察は「この例では」と書く。
平均性能についての説明は、対応する全評価データの集計を根拠にする。
失敗原因の推測は考察として記し、実験で切り分けて確認した原因と混同しない。

#### 4.4 今回のまとめ

今回の結果から言える答えを、第3項の問いに対応させて示す。

「今回取り組んだこと」の単なる再掲ではなく、何を確認できたかを書く。
各結論に対応する結果ページが存在する状態にする。
結論の数は結果に合わせ、無理に3項目へ揃えない。
代表的な数値を載せる場合は条件を添え、新しい実験や未説明の指標をここで初出にしない。
研究全体の目的に対して、今回どの段階を進めたかを短く述べる。
結果の適用範囲を左右する制約は結論にも残す。

例：公開データの分割実験を報告する回では、公開データで確認した分割性能を述べる。
その値から研究室の新生児映像での運動計測や診断への有効性まで達成したとは書かない。

### 5. 課題・今後の展望

**役割：今回分かった限界と、次に行う作業・確認方法を示す。**

前回の課題が今回どこまで解消されたか、新しく見えた課題は何かを整理する。
第2項で挙げた課題と照らし、解消・一部解消・未解消を根拠のある範囲で説明する。
今回の結果を受けた課題と、次回以降の計画を対応させる。

「精度向上」「実用化」とだけ書かず、次の対応を作る。

| 残った課題 | 次に行うこと | 何を見て判断するか |
|---|---|---|
| 結果で確認した問題 | 対象データと変更する処理 | 比較条件、指標、目視確認の観点 |

優先順位を付け、実行時期を決めていない場合は日付を作らない。
第4項の全体図を再掲し、次に進む工程を強調してよい。
内倉さんU05 p.14→29のように、手法説明と研究計画を同じ図で対応させる。

### 6. 付録

**役割：質疑で参照する詳細と、再確認に必要な情報をまとめる。**

モデルの詳細構造、全条件、全クラスの結果、指標の定義、追加の実例、実行記録への対応を置く。
各ページに具体的な見出しを付け、本編のどの取り組みに対応するか分かるようにする。
本編の主張を理解するために必要な条件や重大な制約は、本編にも残す。
目次には「付録」を記載する。未取得の結果を埋めるための仮の付録ページは作らない。

### 新しく作るページの読みやすさ

以下は4:3で新しいページを作る際の出発点。既存固定ページには適用し直さない。
文字の大きさは2026-10-17のユーザー指定。PowerPoint版の位置と部分ごとの大きさは「PowerPoint内AI用_書式指定_20261017.md」を参照。

| 要素 | 制作時の指定 |
|---|---|
| 章・ページの見出し | 28pt、太字 |
| 小見出し | 20pt、太字 |
| 普通の本文 | メイリオ18pt、黒、標準ウェイト |
| 重要な読み取り | メイリオ18pt、赤（#FF0000）、太字 |
| 表・図中の主要ラベル・注記 | 18pt以上。足りなければ列や要素を減らす |
| スライド下部のまとめ | 24pt、赤、太字、中央寄せ。収まらなければ18ptまで小さくしてよい |
| 出典 | 9pt。18pt未満にしてよいのは出典だけ |
| 数式 | PowerPointの数式機能で作る。記号はCambria Math、式の中の日本語はメイリオ、独立した数式は20pt |
| 主要な内容の左右余白 | ページ幅の4～5%程度 |
| 結果画像 | 1枚が主役なら本文領域の大部分を使う |

書誌の補助情報以外の、結論に必要な条件・数値を極小文字へ追いやらない。
長い説明はページ分割かノートへ移す。文字を小さくすることを最初の解決策にしない。
タイトル、図、補助説明の位置を揃え、関連するものを近づける。
画像の縦横比を維持し、比較画像は同じ表示倍率にする。
余白があるだけで埋めようとしない。

### 色と強調

- 通常の文字と見出しは黒（#151515）、強調する語句と画像下の要点は赤（#FF0000）に固定する（2026-10-17に青から変更）。
- スライド最下部のまとめ・要点は、24pt・赤・太字・中央寄せで統一する。収まらない場合は18ptまで小さくしてよい。複数行の場合も各行を中央寄せとする。出典・本文・画像直下の個別説明は従来の配置を維持する。
- 重要な画像領域、今回の工程、注目するセルを囲うときは赤（#FF0000）の四角枠を使う。角丸・楕円・塗りつぶしにはしない。赤は失敗だけでなく注目範囲を示す。
- オレンジは基準資料の見出し線などの装飾に使う。強調文字や注目枠には使わない。
- 表はWebスライド・PowerPoint版とも、見出し行 #F79646・白の太字、データ行は #FCDDCF と #FDEFE9 を1行おき、罫線は白とする。グラフの棒・線は #F79646 を基本色にする（2026-10-17指定。詳細は「PowerPoint内AI用_書式指定_20261017.md」）。
- 見出し・説明文・要点・目次の左に添える装飾用の縦棒は禁止。色・太さを問わず使わない。引用風の左罫線、帯の左端だけに色線を付ける表現も禁止する。強調は赤文字・太字・余白・赤い四角枠で行う。
- メイリオ。タイトル28pt、本文18pt（文字の最小）、下部のまとめ24pt、出典9ptとする（2026-10-17指定）。既存PDFをそのまま再利用する固定ページは元の表示を保持する。
- 一つのページで同時に強調するのは、主な差や観察点の1～2か所を目安とする。
- クラス色、手法色、矢印の意味をページ間で変えない。
- 色だけに意味を持たせず、クラス名・条件名・枠などを添える。
- 写真、表、式、説明枠の全てを同じ強さで目立たせない。

### 学部生向けの用語説明

- 新しく出る専門用語・略語は、平易な日本語の説明を用語付録に用意する。

### 文の書き方

見出しは、そのページで扱う対象を具体的に書く。
「提案手法」だけで区別がつかなければ、ページ内の小見出しに「YOLOによる位置指定」などを添える。
条件説明のページを、根拠のない結論風タイトルへ変えない。

| 避ける表現 | 具体化の方向 |
|---|---|
| 精度が向上した | どの条件と指標で、どれだけ変わったか |
| 有効性を確認した | 何について、どの評価範囲で確認したか |
| 課題が残る | どの部位・場面で、何が失敗したか |
| AIを活用したシステム | 入力に対して、どの処理を行い、何を出力するか |
| 今後は改善する | 何を変え、何を比較して改善を判断するか |

本文に専門語を初めて出す際は、短い日本語の機能説明を添える。
図の内容を本文でも丸ごと繰り返さず、図の見方と読んでほしい差を書く。
数値を使わない仕組み説明でも、入力と出力を具体的にする。

## 6. 研究内容と証拠の扱い

### 必ず対応させるもの

数値、画像、結論ごとに、元の結果ファイル・実行ID・条件を設計書またはノートへ記録する。
スライドには聞き手が判断するための条件を残し、長いパスやハッシュを本文へ並べない。
他者の論文・図・背景情報には出典を付ける。
参考スライド中の医学的・統計的な記述を、新しい事実の根拠として無条件に再利用しない。

### このワークスペースでの重要事項

- 研究処理と結果の扱いは[研究全体方針](../研究全体方針.md)に従う。
- 新しい学習・評価・検証コードは、ユーザーの明示的な実行依頼がなければ実行しない。
- 研究データの変換・集計・研究用グラフ生成が新たに必要なら、保存コードと実行記録の準備まで行い、既存の実行許可の範囲を確認する。資料作成の依頼だけを新しい実験の許可と扱わない。
- 既存結果の読み取り、参考PDFの表示、説明の整理、編集可能なスライド配置と出典の記録は進める。
- 公開データでの分割結果、研究室映像への適用、運動特徴量、医学的評価を、それぞれ実際に確認した範囲で述べる。
- 数値を横並びにするときは、Test、評価座標、解像度、指標の集計法、学習情報、位置指定の違いを確認する。
- 結果の単純平均と、画素面積を合算して得た指標など、計算方法が異なる値を同じ指標として混ぜない。
- YOLO＋SAM2の結果をSAM2単体の自動部位識別結果と書かない。位置指定を固定した比較なら、その条件を記す。
- 平均値の微差を、全例での改善や医学的な意味のある差へ言い換えない。
- 左右が同一クラスの部位マスクを、左右別の運動が測れた証拠として使わない。

### 例として載せる値の扱い

架空の実験値、未実施のグラフ、生成画像を実測の証拠として置かない。
計算の説明に仮の数値を使う場合は、ページ上に「説明用の例」と明示する。
模式図には「模式図」、予想する変化には「仮説」と付ける。
参考資料で使われた値を、自分の結果の仮置きとして使わない。

## 7. AIが実際に作る順序

1. 基準資料と今回の成果を読む。固定する背景・目的のページを特定する。
2. 前回の課題、今回の問い、結果から言える答え、残った課題を対応づける。
3. 指定の6項目の順でスライド設計書を作る。各ページの主図・説明・出典を決める。
4. 現在の基準資料を複製し、固定ページを再利用する。
5. 各ページを本文・図表・注記などの編集可能な要素で組む。
6. 章全体の流れと、各スライドの表示結果を確認して修正する。
7. 求められた形式で納品する。作成依頼なら設計案だけで終了せずPPTXまで仕上げる。指示書・構成案だけの依頼なら、その範囲を守る。

### 設計書の1ページ分の書式

```markdown
### SXX：ページ見出し

- 全体構成の項目：上記6項目のいずれかを正式名称で記入
- 小見出し：第4項なら取り組み名や、データ・方法・結果などを記入
- 扱い：既存固定ページ／新規／既存ページの更新
- このページで答える問い：
- 聞き手に持ち帰ってほしいこと：
- 前ページからの接続：
- レイアウト型：課題実例／データ環境／全体図／工程詳細／比較表／実画像／結論／計画
- 画面上の文章：完成文を記入。制作指示と混ぜない
- 主図：使う実画像・表・図の内容、配置、比較する条件
- 強調：見てほしい1～2か所。囲む箇所や強調するセルまで指定
- 出典：結果ファイル、実行ID、図の元画像、文献
- 説明上の制約：このページだけでは言えないこと
- 発表ノート：図をどう読むか、口頭で補う条件
- 次ページへの接続：
- 想定説明時間：発表条件が分かっている場合に記入
- 未確定事項：なければ「なし」
```

固定ページは本文を新しく書き起こさず、「基準資料のSXXをそのまま再利用」と記録する。

### 編集可能性

新しい見出し・本文はテキストボックス、表はPowerPointの表、説明用の工程図は図形とコネクターなど、後から直せる形にする。
研究画像や保存済みグラフは元ファイルを使用し、読み取りやすいラベルや拡大枠を別の編集可能な要素で添える。
新規ページ全体を1枚の画像にして、編集可能なPowerPointを作ったと扱わない。
固定ページをPDFから画像として再利用した場合は、そのページだけ編集上の制約を明示する。
アニメーションの有無はPDFから分からないため、先輩と同じアニメーションを再現したとは言わない。
順序立てて見せたい説明は、同じ配置を維持した連続スライドでも表現できる。
