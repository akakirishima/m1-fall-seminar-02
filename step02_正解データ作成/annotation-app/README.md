# ローカル画像アノテーション

同じ撮影環境の画像を1枚ずつ表示し、ボタンまたはキーで介入ラベルを付ける自作ツール。
実動画の区間注釈ツールとは別の、本人の最新希望に合わせた入力方式。
画像版は動画を直接読まない。動画を再生し区間を指定する[動画モード](動画区間モード.md)を別画面に追加した。
どちらも動画からのフレーム抽出機能は含まない。

## 起動

リポジトリのルートで実行する。
Python標準ライブラリだけを使い、追加パッケージの導入は不要。

```sh
python3 step02_正解データ作成/annotation-app/serve.py --port 8765
```

ブラウザで http://127.0.0.1:8765 を開く。
サーバーは127.0.0.1だけで待ち受け、公開するディレクトリはこのアプリのフォルダのみ。
画像の送信処理はなく、画像はブラウザ内で表示とSHA-256計算を行う。

## 操作

1. 同じ撮影環境の画像フォルダ、または複数画像を選択する。読み込み時にファイル内容を確認するため、大量の画像は時間がかかる。
2. ROIを描く場合は画像を順番にクリックして囲み、ROI確定を押す。ROIを使わない場合は全画面を選ぶ。
3. 1＝介入あり、2＝介入なし、3＝判定不能。画面ボタンでも入力できる。キーは英数字1文字ずつに変更できる。
4. 初期設定では入力後に次の画像へ進む。←／→で前後へ移動してラベルを訂正できる。
5. 判定不能にはメモで理由を付ける。メモ欄やキー設定欄への文字入力中はラベル用ショートカットを止める。
6. 終了前に作業を保存（JSON）を押す。CSVはラベルの一覧用として使う。

ROIは作業セット内で共有する。
画像ごとに位置の一致を人が確認する。
ROI設定時と画像サイズが違う画像はラベル入力を止める。同じ解像度であってもカメラ位置の違いは検出しない。
ラベルが1枚でも付くと判定範囲をロックし、途中でROIや全画面の定義を変更することを防ぐ。
設定を変えてやり直す必要があれば、現在のJSONを保存し、別のブラウザプロファイルなど独立した作業として開始する。

## 保存と再開

ブラウザのlocalStorageへ画像の識別情報、ROI、メモ、ラベル、位置とキー設定を自動保存する。
画像本体は保存しない。
ブラウザのデータ削除や容量制限に備えて、JSONもダウンロードする。
自動保存できなかった場合は画面に表示する。

再開時は元と同じ方法（フォルダ選択か画像選択）で同じ画像一式を選ぶ。
ファイル名と相対パス、サイズ、SHA-256が一致すれば自動復元する。
JSONからの再開も先に同じ画像一式を選んでから行う。
違う画像集合のJSONは読み込まない。
現在のラベルがある場合のJSON読込は置換になるため確認を出す。

## 出力と研究用データとの関係

独自スキーマframe-annotation-v1を使う。
JSONは画像一覧とSHA-256、元の画像サイズに対する正規化ROI頂点、範囲の種類、ラベル、メモ、更新日時を保持する。
CSVはproject_id、path、sha256、scope、label、note、updated_at。
未ラベル画像も空ラベルで出力し、介入なしへ読み替えない。
ROIの座標はJSONにあるため、CSVだけで作業全体を保管しない。

本アプリのscope=roiのラベルはROI内、scope=full_frameは全画面の手や腕の有無を表す。
従来の区間CSVを検査するvalidate_dataset.pyにそのまま渡す形式ではない。
患者ID、元動画ID、抽出時刻との対応は別途必要で、ファイル名から推測して補わない。
注釈規則の確定、データ分割、本学習向けへの変換は別工程。
表示比率は画像枚数に基づき、判定不能と未ラベルを陽性割合の分母から除く。
作業時間の計測と動画の介入秒数の集計は含まない。
訂正時はその画像のラベルを更新するため、独立注釈や規則変更前のJSONは別名で残す。

## 検証

Playwright CLIからtests/browser-smoke.jsを実行し、一般的な単色PNG3枚で操作を確認した。
実研究画像の注釈やモデル実験とは区別する。
再実行方法はtests/run_smoke.pyを参照する。起動中のローカルサーバーとPlaywright CLIが必要。
